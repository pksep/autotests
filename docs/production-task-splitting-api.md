# API: разделение производственных заданий и операций

Набор `APIProductionTaskSplitting.spec.ts` подключён через `runProductionTasksAPINew`.
Он входит в `production_tasks_api` и общие API-наборы, использующие этот runner, включая `all_api_tests`.

Проверяются реальные маршруты и DTO из серверного проекта:

- `POST api/production-task/:sourceProductionTaskId/subtasks` — одна позиция на запрос,
  целое положительное количество, минимум 1 шт. остаётся в исходном ПЗ.
- `POST api/production-task/operation-positions/:operationPositionId/assignments` —
  одиночная доля, пакет `assignments`, совместимый `additionalAssignments` и атомарное удаление/добавление долей.

## Покрытие

30 тестов: по 15 для сборки (`ass`) и металлообработки (`metall`).
Негативные варианты DTO и бизнес-ограничений проверяются отдельными шагами внутри тестов.

| Сценарий | Проверяемый результат |
|---|---|
| Дочернее ПЗ и повторное разделение дочернего | Общий корень, номера детей, наследование срока/описания/операций, новые исполнители/станки |
| Количество ПЗ | Сумма количеств сохраняется, `quantity_max` соответствует остатку, минимум 1 шт. остаётся в источнике |
| Ошибочные DTO и назначения ПЗ | HTTP 400/409, нет детей и изменения исходной позиции |
| Разделение из вторичной доли | Количество уменьшается у выбранного источника, остальные доли сохраняются |
| Сохранение нескольких долей | Обе формы пакета сохраняются полностью, сумма долей равна количеству позиции |
| Ресурс производства | Для сборки уникален сотрудник; для металлообработки уникален станок, один сотрудник может работать на разных станках |
| Удаление и повторное назначение | Количество возвращается основному назначению; новая запись получает новый ID и свободный приоритет |
| Ошибка второй доли | Все предыдущие добавления и удаления того же пакета откатываются |
| Квалификация и оборудование | Неквалифицированный сотрудник, чужой станок и отсутствующий станок металлообработки отклоняются |
| Принадлежность сущностей | Реальные позиции, операции и назначения другого ПЗ не изменяют ни один источник |
| Выполненное количество | Отметка остаётся на месте, выполненные штуки сохраняются при разделении/удалении и не могут быть перенесены |
| Разделённая операция и разделение ПЗ | Позицию с долями нельзя переносить в дочернее ПЗ |
| Архив и авторизация | Архивный источник возвращает 404; недействительный токен возвращает 401, данные не меняются |

## Изоляция и очистка

Для каждого вида производства создаются собственная деталь/СЕ, техпроцесс, квалифицированный тип операции,
операция и заказ склада. Существующие сотрудники и станки используются как справочники ресурсов.
В каждом тесте создаётся собственное ПЗ на 10 шт. Производственные задания и отметки очищаются после теста;
созданные справочные сущности архивируются после группы. Ошибки очистки не скрываются.

Автоматические операции тестовой СЕ архивируются, а единственная тестовая операция получает индекс 1.
Это позволяет проверять разделение и отметки без зависимости от складской комплектации.

## Запуск

Через штатную точку входа `main.spec.ts`, без `API_INDEPENDENT_TESTS` и `API_NO_AUTH`:

```powershell
$env:TEST_SUITE='production_tasks_api'
$env:API_BASE_URL='https://dev.pksep.ru/'
$env:BASE_URL='https://dev.pksep.ru/'
pnpm exec playwright test --grep 'Production Tasks API: разделение' --workers=1
```

Для полного набора API используются `TEST_SUITE=all_api_tests` и `pnpm test`.
