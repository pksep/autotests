# Анализ тестового покрытия ERP-системы и выявление пробелов

На основе всестороннего анализа карты элементов ERP-системы и существующих наборов тестов `U001-U007`, в данном документе определено, что в настоящее время покрыто тестами, а также указаны **модули, запланированные для дальнейшего покрытия** автоматизацией.

## 🟩 Полностью покрытые модули

Для этих модулей созданы надежные сценарии автоматизации пользовательского интерфейса.

| Модуль | Основной функционал | Покрывающие наборы тестов |
| :--- | :--- | :--- |
| **База продукции** (/baseproducts) | Создание и управление Изделиями, Сборками и Деталями. Включает структуру спецификаций (BOM), валидацию UI и обработку ошибок при некорректном вводе. | `U001-Setup`, `U004`, `U005`, `U006` |
| **Производство / Склад** (/production) | Запуск в производство дефицитных позиций, перемещение материалов между складом и производственными очередями. | `U001-Assembly`, `U001-Production`, `U001-Receiving` |
| **Задачи на отгрузку** (/issues) | Сквозной процесс создания задач по заказам клиентов, включая маршрутизацию выполнения. | `U001-Orders`, `U001-Shipment`, `U003` |
| **Действия (Журнал аудита)** (/actions) | Непрерывный трекинг генерируемых пользователем событий (создание, редактирование, архивация). | `U007-Actions` |

## 🟨 Частично покрытые модули

Эти модули затрагиваются тестами, но в основном выступают в качестве поддерживающих зависимостей. Они не имеют специализированных углубленных тестов валидации.

| Модуль | Основной функционал | Текущее состояние |
| :--- | :--- | :--- |
| **База материалов** (/basematerials) | Стандартная база сырья и покупных деталей. | Динамически создаются во время `U001-Setup`, но специализированных тестов на отказоустойчивость, подобных `U006` для Деталей, не существует. |
| **Результаты работы** (/resultwork) | Журналы смен сотрудников и учет времени на основе выполненных задач через «Онлайн-табло». | Поверхностно затрагивается в `ERP-3015.spec.ts`, но отсутствуют строгие проверки расчетов (например, проверка того, что зарегистрированные часы математически соответствуют производственным показателям). |

## 🟦 В планах: Вспомогательные базы

ERP-система содержит несколько «Вспомогательных баз», которые находятся в приоритете для дальнейшего покрытия UI тестами. Эти модули управляют оценкой запасов, учетом оборудования и поиском документов.

| Модуль | Назначение | Предлагаемое действие |
| :--- | :--- | :--- |
| **База файлов** (/filebase) | Центральное хранилище технических спецификаций и чертежей (PDF, SLDDRW, DXF). | Высокий приоритет. Требуется тест, который загружает файл, проверяет его появление в глобальной таблице и успешно привязывает его к Продукту в «Базе продукции». |
| **База инструмента и оснастки** (/basetools) | Учет производственных инструментов, пресс-форм и измерительных приборов (например, штангенциркули, патроны). | Средний приоритет. Требуется базовый сценарий тестирования CRUD, имитирующий `U005`, для проверки работы UI компонентов. |
| **База оборудования** (/baseequipment) | Управление тяжелой техникой и активами производственных линий. | Низкий/Средний приоритет. Требуются стандартные тесты создания/редактирования. |
| **База техники и инвентаря** (/inventary) | Учет складского инвентаря (подъемники, внешний транспорт). | Низкий приоритет. Требуется стандартное покрытие CRUD. |
| **Контрагенты / Компании** (/baseprovider, /basebuyer) | CRM-функционал по работе с поставщиками, клиентами и отдельными контактами. | Средний приоритет. Требуется проверка того, что данные корректно подвязываются к «Задачам на отгрузку» (пункты назначения доставки заказов). |

## 🟦 В планах: Глобальные настройки (/settings)

Панель `/settings` служит главным порталом конфигурации для всей ERP-системы. Она содержит 15 различных управляющих таблиц. Эти страницы настроек являются фундаментом для всех остальных модулей и запланированы для скорого покрытия автоматизированными UI тестами.

| Раздел настроек | Назначение | Предлагаемое действие |
| :--- | :--- | :--- |
| **Базовые настройки** (`/settings/savebasedata`) | Основные системные справочники и глобальные константы. | Высокий приоритет. Это определяет глобальное состояние приложения. |
| **Сотрудники и доступы** (`/settings/employee`, `rolesuser`, `dolznuser`) | Создание сотрудников, назначение ролей и должностей. | Высокий приоритет. Требуется для тестирования ролевой модели (RBAC). |
| **Финансы и Время** (`/settings/pricehors`, `uthetwtime`) | Нормочасы и параметры учета рабочего времени. | Высокий приоритет. Напрямую влияет на точность «Результатов работы». |
| **Настройки баз данных** (`/settings/materials/:id`, `instrosn`, `baseoborud`, `basetech`) | Административная панель для заполнения Заготовок, Покупных деталей, Расходников, Инструмента, Оборудования и Инвентаря. | Средний приоритет. Нужны базовые CRUD тесты для проверки того, что администраторы могут добавлять/удалять атрибуты. |
| **Производственные настройки** (`/settings/opertechproc`, `diffsklad`, `edizm`) | Единицы измерения, технологические операции и калькуляторы дефицита. | Средний приоритет. |

## Дальнейшие шаги

Для устранения наиболее критических пробелов мы рекомендуем писать тестовые сценарии в следующем порядке:

1.  **Интеграция базы файлов (`U008-Files.spec.ts`)**: Возможность размещения и привязки инженерных чертежей и PDF к данным деталей — ключевое преимущество ERP. Этот процесс сейчас не тестируется.
2.  **Расчет результатов работы (`U009-WorkResults.spec.ts`)**: Поскольку раздел «Результаты работы» тесно связан с расчетом заработной платы и показателями эффективности сотрудников, ошибки здесь имеют реальные финансовые последствия. Нам нужны строгие математические проверки этой таблицы.
3.  **CRM / Вспомогательные базы (`U010-AuxiliaryBases.spec.ts`)**: Объединить создание/удаление инструментов, оборудования и компаний в единый эффективный набор тестов для быстрого восполнения оставшегося пробела в покрытии.
